# 🎉 KTB 커뮤니티 백엔드 서버

이 프로젝트는 **커뮤니티 웹사이트의 뒷단(백엔드) 서버**입니다. 쉽게 말하면 웹사이트가 작동할 수 있게 도와주는 엔진 같은 역할을 해요!

## 📚 이 문서를 읽기 전에 알아두면 좋은 것들

### 백엔드가 뭐예요? 🤔

웹사이트는 두 부분으로 나뉩니다:
- **프론트엔드**: 우리가 화면에서 보는 것들 (버튼, 입력창, 이미지 등)
- **백엔드**: 화면 뒤에서 데이터를 처리하고 저장하는 부분

예를 들어, 게시글을 쓰고 "올리기" 버튼을 누르면:
1. 프론트엔드: 버튼 클릭 감지 👆
2. 백엔드: 게시글 데이터를 데이터베이스에 저장 💾
3. 프론트엔드: "저장 완료!" 메시지 표시 ✅

이 프로젝트는 2번을 담당하는 백엔드 서버예요!

## 🎯 이 프로젝트가 하는 일

이 백엔드 서버는 다음과 같은 기능들을 제공합니다:

### 1️⃣ 사용자 관리 👤
- 회원가입: 새로운 사용자 등록
- 로그인: 사용자 인증 (JWT 토큰 사용)
- 프로필 관리: 사용자 정보 조회/수정

### 2️⃣ 게시글 관리 📝
- 게시글 작성: 새로운 게시글 올리기
- 게시글 조회: 게시글 목록 보기, 상세 보기
- 게시글 수정/삭제: 내가 쓴 게시글 관리
- 이미지 업로드: 게시글에 사진 첨부 (AWS S3 사용)

### 3️⃣ 댓글 관리 💬
- 댓글 작성: 게시글에 댓글 달기
- 댓글 조회: 댓글 목록 보기
- 댓글 삭제: 내 댓글 삭제

### 4️⃣ 좋아요 기능 ❤️
- 좋아요 누르기/취소: 게시글에 좋아요 표시

## 🛠️ 이 프로젝트에서 사용하는 기술들

### Java + Spring Boot ☕
- **Java 21**: 프로그래밍 언어 (가장 최신 버전!)
- **Spring Boot 3.3.4**: 웹 서버를 쉽게 만드는 프레임워크
- 마치 레고 블록을 조립하듯이 웹 서버를 빠르게 만들 수 있어요!

### 데이터베이스 🗄️
- **MySQL 8.0**: 데이터를 저장하는 곳
  - 게시글, 댓글, 사용자 정보 등을 저장
  - 마치 엑셀 파일처럼 데이터를 정리해서 보관해요

### 보안 🔐
- **JWT (JSON Web Token)**: 로그인 인증에 사용
  - 사용자가 로그인하면 토큰을 받고, 이 토큰으로 "나는 로그인한 사용자야!"라고 증명해요
  - 마치 입장권 같은 거예요! 🎫

### 파일 저장 📦
- **AWS S3**: 이미지 파일을 저장하는 곳
  - 게시글에 올린 사진들을 클라우드에 안전하게 보관해요
  - 마치 구글 드라이브처럼요!

### 배포 🚀
- **Docker**: 서버를 컨테이너로 감싸서 배포
  - 프로그램을 실행하는 환경을 한 번에 만들어요
  - 마치 게임 CD를 넣으면 바로 실행되는 것처럼!
- **GitHub Actions**: 코드를 푸시하면 자동으로 배포
  - 코드를 GitHub에 올리면 자동으로 서버에 반영되어요!

## 📂 프로젝트 구조 (폴더 설명)

```
3-caleb-son-community-BE/
├── src/main/java/com/ktb/community/
│   ├── controller/        # 컨트롤러: 사용자 요청을 받는 곳 (문지기 같은 역할)
│   │   ├── PostController.java      # 게시글 관련 요청 처리
│   │   ├── CommentController.java   # 댓글 관련 요청 처리
│   │   └── UserController.java      # 사용자 관련 요청 처리
│   │
│   ├── service/          # 서비스: 실제 비즈니스 로직 처리 (일꾼 같은 역할)
│   │   ├── PostService.java         # 게시글 처리 로직
│   │   ├── CommentService.java      # 댓글 처리 로직
│   │   └── UserService.java         # 사용자 처리 로직
│   │
│   ├── repository/       # 리포지토리: 데이터베이스와 대화하는 곳 (도서관 사서 같은 역할)
│   │   ├── PostRepository.java      # 게시글 데이터 조회/저장
│   │   ├── CommentRepository.java   # 댓글 데이터 조회/저장
│   │   └── UserRepository.java      # 사용자 데이터 조회/저장
│   │
│   ├── domain/           # 도메인: 데이터 구조 정의 (레고 블록 설계도 같은 역할)
│   │   ├── Post.java     # 게시글 데이터 구조
│   │   ├── Comment.java  # 댓글 데이터 구조
│   │   └── User.java     # 사용자 데이터 구조
│   │
│   ├── dto/              # DTO: 데이터 전송 객체 (우편함 같은 역할)
│   │   └── ...
│   │
│   ├── filter/           # 필터: 요청을 가로채서 검사하는 곳 (보안검색대 같은 역할)
│   │   └── JwtAuthenticationFilter.java  # 로그인 토큰 확인
│   │
│   └── util/             # 유틸리티: 유용한 도구들
│       └── JwtUtil.java  # JWT 토큰 만들기/검증하기
│
├── src/main/resources/
│   └── application.yml   # 설정 파일 (서버 설정, DB 연결 정보 등)
│
├── Dockerfile            # Docker 이미지를 만드는 방법서
├── docker-compose.yml    # 여러 프로그램을 한 번에 실행하는 설정
├── build.gradle.kts      # 필요한 라이브러리 목록 (도구 상자 같은 역할)
└── .github/workflows/    # 자동 배포 설정 (로봇 같은 역할)
    └── deploy.yml
```

### 각 폴더의 역할을 쉽게 설명하면:

1. **Controller**: 사용자가 "게시글 보여줘!"라고 요청하면 받아서 Service에 전달
2. **Service**: "게시글 보여줘" 요청을 받아서 실제로 어떻게 처리할지 결정
3. **Repository**: Service가 "데이터베이스에서 게시글 가져와!"라고 하면 가져옴
4. **Domain**: 게시글이 어떤 정보를 가져야 하는지 정의 (제목, 내용, 작성자 등)

## 🚀 프로젝트 실행하기

### 방법 1: 로컬에서 실행 (개발용)

```bash
# 1. 프로젝트 폴더로 이동
cd 3-caleb-son-community-BE

# 2. 필요한 라이브러리 다운로드 및 빌드
./gradlew build

# 3. 서버 실행
./gradlew bootRun
```

서버가 실행되면 `http://localhost:8080`에서 확인할 수 있어요!

### 방법 2: Docker로 실행 (배포용)

```bash
# 1. Docker 이미지 빌드
docker build -t community-backend:latest .

# 2. Docker Compose로 실행 (MySQL과 함께)
docker-compose up -d
```

## 📡 API 엔드포인트 (사용자 요청 주소들)

서버가 어떤 요청을 받을 수 있는지 알아보기:

### 사용자 관련 👤
- `POST /api/users/signup` - 회원가입
- `POST /api/users/login` - 로그인
- `GET /api/users/{id}` - 사용자 정보 조회
- `PUT /api/users/{id}` - 사용자 정보 수정

### 게시글 관련 📝
- `GET /api/posts` - 게시글 목록 조회
- `GET /api/posts/{id}` - 게시글 상세 조회
- `POST /api/posts` - 게시글 작성 (로그인 필요)
- `PUT /api/posts/{id}` - 게시글 수정 (작성자만)
- `DELETE /api/posts/{id}` - 게시글 삭제 (작성자만)

### 댓글 관련 💬
- `GET /api/posts/{postId}/comments` - 댓글 목록 조회
- `POST /api/posts/{postId}/comments` - 댓글 작성 (로그인 필요)
- `DELETE /api/comments/{id}` - 댓글 삭제 (작성자만)

### 좋아요 관련 ❤️
- `POST /api/posts/{id}/like` - 좋아요 누르기/취소 (로그인 필요)

## 🔄 자동 배포 과정 (GitHub Actions)

코드를 GitHub에 푸시하면 자동으로 배포됩니다:

1. **코드 푸시** → GitHub에 코드 올리기
2. **빌드 시작** → GitHub Actions가 자동으로 시작
3. **테스트 실행** → 코드가 제대로 작동하는지 확인
4. **이미지 빌드** → Public EC2에서 Docker 이미지 생성
5. **이미지 전송** → Private EC2로 이미지 전송
6. **서버 재시작** → 새 버전으로 서버 재시작
7. **완료!** ✅

자세한 내용은 [DEPLOYMENT.md](./DEPLOYMENT.md)를 참고하세요!

## 🗄️ 데이터베이스 구조

### User (사용자) 테이블
- `id`: 사용자 고유 번호
- `username`: 사용자 이름
- `email`: 이메일
- `password`: 비밀번호 (암호화되어 저장)
- `createdAt`: 가입 날짜

### Post (게시글) 테이블
- `id`: 게시글 고유 번호
- `title`: 제목
- `content`: 내용
- `authorId`: 작성자 ID (User와 연결)
- `createdAt`: 작성 날짜
- `updatedAt`: 수정 날짜

### Comment (댓글) 테이블
- `id`: 댓글 고유 번호
- `content`: 댓글 내용
- `postId`: 게시글 ID (어떤 게시글의 댓글인지)
- `authorId`: 작성자 ID (User와 연결)
- `createdAt`: 작성 날짜

### PostLike (좋아요) 테이블
- `postId`: 게시글 ID
- `userId`: 사용자 ID
- 좋아요는 게시글과 사용자 쌍으로 저장
